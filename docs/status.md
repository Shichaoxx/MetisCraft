设计规格见 [`design.md`](design.md)。MetisCraft 是新名字、新包，版本号从 `0.1.0.dev0` 重新开始。开发在 `toolkit-rewrite` 分支，升级完成后再接替 `main`。这是开发版，文档里标"待定"的地方都是开发进行中的状态。

## 定位

MetisCraft 是工具包，不是某个模型或某个任务的项目。它由两部分组成：

- **支持矩阵**：收录当前较好的 Jev 类（System One）决策模型与训练项目，每行标出能否用 MetisCraft 训练、复现、部署。2026-11-04 起取代原定的单独 Awesome 调研清单。
- **训练工具包**：做 Jev 类决策模型领域的 LlamaFactory / Unsloth，目标有两层：一是支持通用的 judge；二是，也是更重要的，让特定的垂直业务场景也能做成自己的 Jev——给定场景的数据和判断类型，用配方训练、校准、评测并部署。模型一次前向给出结构化判断（是非、选择、等级打分、排序、多标签）和校准过的概率；模型、读出、训练目标、微调方式、数据、训练与推理后端都可以组合替换。训练好的模型通过 Predictor 和 HTTP 服务部署。

## 设计理念

"训练有素的直觉"：把大模型的慢思考训练成又快、又知道自己有多准的判断。

- **快**：一次前向给出判断。
- **知道自己有多准**：校准是一等公民。
- **判断有类型**：是非、选择、等级、排序、多标签各有明确的输入输出约定。
- **能从反馈中学**。

工程上：部件可换、一事一处、有据可查、借力成熟库；以及**看得见**——每步计算都能画成张量图，图与代码一一对应。第一版做张量教学图和"图与代码对齐"；按配置自动画图的 `metiscraft viz` 先设计，核心闭环跑通后实现。图用 Tectonic 编译。

## 名字与许可证

项目名 **MetisCraft**（2026-11-03 确定）：包名、import、命令行统一为 `metiscraft`，PyPI、GitHub、Hugging Face 均无同名。希腊语 mētis 指工匠与航海者因时因地的实践智慧，兼有手艺与机巧两层；英语 craft 同样兼有这两层，是它的译名。原名 `metis` 在 PyPI 已被 METIS 图划分库的封装占用，AI 领域同名项目也多。

许可证 Apache-2.0，见 [`LICENSE`](../LICENSE)。

## 已定

- **支持矩阵代替单独的清单**：首版见 [`support-matrix.md`](support-matrix.md)（13 个项目，首批 5 个），逐步扩到约 10–20 个；先前的 Awesome 清单草稿只作素材。
- **v0.1 的部署范围**：Predictor，外加一层沿用 `/v1/systemone` 请求格式的 HTTP 服务，保留按类型的校准；vLLM、SGLang、llama.cpp 的引擎导出放到 v0.2，随首发基座的选择而定。
- **通用 judge 与垂直场景**：支持通用的类型化判断，更重要的是让垂直业务场景也能做成自己的 Jev（场景用配方适配）；不设单一业务旗舰；v0.1 验收每种判断类型各用一个公开基准（见下）。
- **数据注册表和主流数据集支持是 v0.1 必需项**：用开源数据集训练和验收；注册表收录主流通用数据集和 Jev 类数据集（Open-Jev、tasksource-jev-typed-decisions、LocalLLaMA typed-decisions 等），首批名单见下，核对详情见 [`research/datasets.md`](research/datasets.md)。数据契约原生读取 Jev 类型化判断格式（`state` + `questions` + 目标），与 HTTP 服务的请求格式一致。
- **构建与范围（2026-11-05）**：自建可组合核心，ms-swift / HF 适配层放 v0.2；v0.1 判断类型为是非、选择、等级、多标签，排序放 v0.2；首发基座 Qwen3 0.6B–4B；v0.1 必须有一对可对照的读出：选择题上，答案 token 与逐候选标量头只改配置就能互换。
- **首批数据集与验收（2026-11-05）**：按 [`research/datasets.md`](research/datasets.md) 注册必收、可选、只评测三档；条款受限的 AG News、MS MARCO、NFCorpus、SST-5 也收，带条款标记，用它们训练的权重不标可商用。v0.1 验收：是非 BoolQ，选择 Banking77（CLINC150 作对照），等级 SST-5，多标签 GoEmotions `simplified`。
- **补上开源、可复现的类 Jev 训练过程（2026-11-05）**：类 Jev 模型普遍没有完整开源训练过程（见支持矩阵"训练过程公开程度"）。MetisCraft 的每次运行都留下配置、数据版本、提交、环境与逐题评测，下一阶段用它把公开了配方的项目端到端复现、补齐缺的数据与超参，并训练一个训练过程完全公开的通用小 Jev。

## 竞品与空白

- ms-swift（`--task_type decision`）和 Unsloth 已经能训练决策模型，transformers #50054 与 TRL #8040 正在标准化，"训练工具稀缺"不再成立。
- 剩下的空白：完整开源、可复现的训练过程（类 Jev 模型里没有一个做到）；多标签加逐候选校准；读出与基座解耦、在同一协议下对照；业务配方、可追溯评测与支持矩阵。
- 诚实边界：有标签时 encoder 往往更准；自己训练的理由是私有化、校准、多标签或排序、选项集可变。详见 [`design.md`](design.md) §2。

## 早期版本 Metis 0.1.0（已归档）

tag `metis-v0.1.0`，提交 `fac3a4d`。它是一个候选打分任务的示例：Qwen3 Base + MLP ScoreHead 候选打分、NFCorpus 排序闭环、BoolQ 读出研究，以及未实现的 v2 升级方案。

重写原因：

1. **没有可替换的部件。** 模型只支持 Qwen3，任务靠 if/else 分支，只有打分用的监督损失，训练是单个 `train()` 函数，只能单卡。
2. **自己的实验绕开了工具包。** BoolQ 研究脚本各自写训练循环、LoRA 接入和保存格式，研究代码多于核心库。
3. **唯一的模型没训好，也缺对照。** NFCorpus test nDCG@10 为 0.291，低于原始 Qwen3-Reranker 的 0.355，且未报告 BM25 本身的分数；BoolQ 第二轮的 9 个模型在阈值 0.5 下把 384 条预留评测样本全部预测为肯定。更可能的原因是欠训练（NFCorpus 最好的检查点就是最后一步，2 个 epoch 时 dev 仍在上升）和表示判别力弱（BoolQ 冻结特征探针都低于多数类）；NFCorpus 那次也只跑了一个种子、没有扫学习率、没有强基线。早先记录的"LoRA 学习率 2e-5 偏低"证据不足，已撤回：那次诊断同时改了 LoRA 和头的学习率，2e-5 那组也能拟合；代码默认值 2e-6 是真缺陷，但没有影响已报告的数字。
4. **v2 方案仍在给这一个模型补功能**，做完也不是工具包。

数据契约、NFCorpus 准备与评测、张量图等可复用部分按需从 tag 取回，不整体继承。
