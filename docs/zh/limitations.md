# 当前边界与证据

MetisCraft 0.1.0rc1 是发行候选版，接口和产物格式仍可能变化。CPU 快速上手成功只说明
打包后的流程能够运行；随机模型和构造数据不能证明模型效果。

## 模型效果证据

按评测前记录的标准，Qwen3.5-4B 的 Tev1 复现已**达到准确率验收标准**：

| 题集 | MetisCraft，Qwen3.5-4B | Tev1 公布结果，Qwen3.5-4B | 状态 |
|---|---:|---:|---|
| `test`，1,000 题 | 87.3%（873／1,000） | 88.0% | 差距在预定的 2 个百分点以内 |
| `policy_transfer`，300 题 | 99.33%（298／300） | 100% | 符合接近 100% 的要求 |

此前 2B 的结果是 86.4%／92.0%。已完成的 4B 逐题对照核对了 ID、输入、金标与
选项顺序；主集答案一致率为 94.6%，迁移集为 99.33%。原版报告使用温度 0、按选项
regex 约束生成，MetisCraft 采用候选字母内最大值。无约束全词表首 token 诊断尚未做，
不能把它与原版已报告的协议混为一谈。准确率接近不等于恢复未知的历史训练超参或得到
相同权重。本轮只跑一个种子，上游也在开发过程中使用过这些题，因此不能据此推断
未接触任务上的泛化能力。细节见 [Tev1 记录](../reproductions/tev1.md)。

已公布的 GoEmotions 运行使用的是 `pos_weight` 推理修复前的代码。离线修正分数不等于
已经用修复后的代码完成训练重跑，详见[配方结果](../../recipes/go_emotions/README.md)。

相同划分、指标和校准协议下的 encoder 基线尚未完成。目前这些结果不能证明相对 encoder
的准确率或成本优势。

## 软件范围

- 实现了两种读出；排序不在本版范围内。
- HTTP 端点支持三种判断，多标签预测通过 Record API 使用。
- 服务使用 Transformers 和 Predictor，尚未实现 vLLM、SGLang 或 llama.cpp 导出。
- 暂无受支持的断点续训流程。
- 模型架构支持取决于安装的 Transformers 版本，未验证全部模型家族与 GPU 内核。
- 本地 HTTP 服务不包含身份认证或完整的生产运维设施。

## 如何理解身份校验与校准

文件身份用于发现相对于已记录字节的变化，不能证明上游真实性、恢复缺失的历史证据，
也不能验证标签正确性。导入的许可证和来源字段属于声明，不代表已独立核实权利与出处。

分布变化后，温度校准可能使结果变差。4B Tev1 运行在应用拟合出的 policy 温度后，
policy-transfer 的 NLL 从 0.0522 升至 0.0990，准确率不变，原因仍待查。
应在有代表性的留出数据上对照校准前后指标，
并保持各划分用途独立。
